Команда повторения отчёта из корня проекта после установки зависимостей:

```bash
python scripts/verify.py --output /tmp/taskflow-verification.json
```

В отчёте `source_commit` указывает на `39cfbe71e5960ef8c4b7637d769444d34c94d260` (`baseline-mvp`). Файлы приложения/тестов/шаблонов/стилей/bootstrap/verifier/requirements в ЭК1 не менялись; это дополнительно проверено по `source_sha256`. Документальные добавления и CI после baseline не изображают изменение поведения продукта. Хеши позволяют проверить содержимое и без `.git` после распаковки архива.

Пять проверок: совместимость установленных пакетов (`pip check`), Django system check, отсутствие несозданных миграций, тесты поведения и защитных свойств, non-debug `check --deploy --fail-level WARNING`. Тесты используют отдельную тестовую БД и синтетический временный секрет. Вывод не содержит рабочий `.env` или пароль.

Браузерная проверка: `demo-owner` вошёл, открыл доску, создал учебную задачу; `demo-viewer` вошёл, прочитал её на доске без управляющих кнопок; прямое открытие формы создания показало страницу 403. Проверка выполнялась на локальной БД, которая намеренно не входит в архив. Для повторения созданий используйте README и свои demo-данные. Исходный скриншот снят до добавления дополнительной smoke-задачи.

Свежие результаты CI доступны в [GitHub Actions](https://github.com/rbeketov/rbpo-yavkaib/actions); нужно проверять commit запуска, а не переносить зелёный статус между версиями. Наличие workflow или успешного запуска не подтверждает обязательный status check в настройках репозитория.

SHA-256 итогового ZIP и результат проверки распакованного комплекта предоставляются рядом с архивом, поскольку архив не может включать собственный контрольный хеш. Сам `git archive` не содержит Git-историю: baseline доступен в общем репозитории по тегу/commit из паспорта.
