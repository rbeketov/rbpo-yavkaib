# TaskFlow · ЯвкаИБ

Учебный трекер задач для курса «Разработка безопасного ПО», НИУ ВШЭ, 2026/2027.
Работающий локальный MVP: проекты, доска с тремя статусами, текстовые комментарии и три роли внутри каждого проекта.

**Команда:** Бекетов Роман Александрович ([rbeketov](https://github.com/rbeketov)), Кузьмин Ярослав Артёмович ([yarikTri](https://github.com/yarikTri)).
Планируемый продуктовый выпуск — `v1.0.0`. Учебные теги `baseline-mvp` и `ek1` имеют отдельное назначение и не означают выпуск в промышленную эксплуатацию.

## Запуск за несколько минут

Нужны **Python 3.12** с `venv`/`pip` и интернет для установки зависимостей с PyPI. Проверенная версия — Python 3.12.14; Django 5.2.17, asgiref 3.12.1, sqlparse 0.6.0 зафиксированы в [requirements.txt](requirements.txt). Команды ниже — для macOS/Linux, из корня распакованного архива или клона репозитория.

```bash
python3.12 scripts/bootstrap.py
source .venv/bin/activate
set -a
source .env
set +a
python manage.py migrate
python manage.py seed_demo
python manage.py runserver 127.0.0.1:8000
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). `bootstrap.py` создаёт локальную `.venv` и `.env` со случайным секретом; существующий `.env` сохраняется. Django сам `.env` не читает — команды `source` обязательны в каждом новом терминале. Секрет не нужно копировать в код.

`seed_demo` попросит придумать пароль из 12 и более символов для четырёх **синтетических локальных** аккаунтов:

| Аккаунт | Доступ к проекту «Запуск TaskFlow» |
| --- | --- |
| `demo-owner` | Владелец |
| `demo-editor` | Редактор |
| `demo-viewer` | Наблюдатель |
| `demo-outsider` | Нет доступа; имеет собственный отдельный проект |

Один введённый пароль используется только для этих демонстрационных аккаунтов. Не используйте пароль от реальной учётной записи. Повторное заполнение не удаляет данные и не меняет существующие пароли; явный `python manage.py seed_demo --reset-passwords` сбрасывает пароли только demo-аккаунтов. Команда отказывается работать вне debug-режима.

Остановка сервера — `Ctrl+C`. Для повторного запуска загрузите `.env`, активируйте `.venv` и выполните `runserver`. База `db.sqlite3` локальная, не входит в Git и архив; демонстрационные данные воспроизводятся командой `seed_demo`.

Для Windows: `py -3.12 scripts/bootstrap.py`, затем `.venv\Scripts\Activate.ps1`. Переменные из локального `.env` нужно задать в текущем PowerShell (`$env:TASKFLOW_SECRET_KEY`, `$env:TASKFLOW_DEBUG`, `$env:TASKFLOW_ALLOWED_HOSTS`); далее команды `python manage.py ...` те же. Windows отдельно не проверялся.

## Что можно делать

Любой вошедший пользователь может создать собственный проект. Владелец добавляет уже существующих пользователей по имени; роль действует только в этом проекте. Владелец другого проекта и Django superuser не получают обхода проверки членства.

| Действие | Владелец | Редактор | Наблюдатель | Вне проекта |
| --- | --- | --- | --- | --- |
| Читать проект, задачи, комментарии | Да | Да | Да | Нет |
| Создавать/изменять задачи, писать комментарии | Да | Да | Нет | Нет |
| Удалять задачи/проект | Да | Нет | Нет | Нет |
| Добавлять участников, менять роли, отзывать доступ | Да | Нет | Нет | Нет |

Владелец задаётся сервером при создании проекта; передача владения не реализована. У задачи статусы «К выполнению», «В работе», «Завершена». Участник без нужной роли получает 403, посторонний — 404. Скрытие кнопок в интерфейсе дополнено проверками на сервере.

## Повторить проверки

```bash
python scripts/verify.py
```

Скрипт сам задаёт временную конфигурацию тестов и выполняет `pip check`, системные проверки Django, проверку миграций, 27 тестов с подслучаями для ролей и проверку настроек вне debug-режима. Рабочая база не используется тестами. Ненулевой код возврата означает сбой.

```bash
python scripts/verify.py --output /tmp/taskflow-verification.json
```

JSON содержит версии, команды, результаты и SHA-256 исходников. Успешные тесты не доказывают отсутствие всех уязвимостей; `pip check` проверяет совместимость зависимостей, а не CVE. Публичное развёртывание и промышленная конфигурация этим комплектом не подтверждаются.

## Устройство и ограничения

Браузер → Django (сессия, CSRF, формы, проверка доступа) → SQLite. Серверные HTML-шаблоны, локальный CSS; внешних сервисов при работе нет.

- [tracker/permissions.py](tracker/permissions.py), [tracker/views.py](tracker/views.py) — серверные права и действия.
- [tracker/models.py](tracker/models.py), [tracker/forms.py](tracker/forms.py) — данные и допустимые поля ввода.
- [tracker/tests.py](tracker/tests.py) — разрешённые и запрещённые сценарии, CSRF, экранирование текста.
- [taskflow/settings.py](taskflow/settings.py) — параметры среды и конфигурация.

Нет регистрации, почты, вложений, API интеграций и промышленного деплоя. Вход не имеет ограничения частоты попыток; это ограничение локального MVP, а не повод выставлять его в интернет. `DEBUG=1` и HTTP разрешены только для локальной демонстрации на `127.0.0.1`. Не публикуйте `.env`, базу, реальные пароли и пользовательские данные.
